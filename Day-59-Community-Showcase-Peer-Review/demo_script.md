# Day 59 — AI Research Assistant Demo

## 0:00–1:00 — Introduction and User Problem
Introduce the product and explain the user problem it aims to solve.
Use a real example of a question a user might ask.

## 1:00–3:00 — Architecture
Explain the actual frontend, backend API, retrieval pipeline, language model, and data sources.
Show the architecture diagram.
Only describe components that are actually implemented.

## 3:00–5:30 — Three Engineering Decisions
1. Retrieval strategy: explain the approach used and its trade-offs.
2. Backend/API design: explain the actual framework and API boundaries.
3. Evaluation and reliability: explain testing, error handling, and limitations.

## 5:30–7:00 — Evaluation Results
Show the real evaluation dataset, test count, measured score, and important failure cases.
If evaluation has not been run, say so and explain the planned measurement.

## 7:00–8:30 — Live Demo
Run a realistic query, show the response, and explain where the supporting context comes from.
Do not expose API keys, personal data, or secrets.

## 8:30–9:30 — What I Would Build Differently
Explain one specific architectural or engineering change and why it would help.

## 9:30–10:00 — Conclusion
Summarize the main learning and invite technical questions.
